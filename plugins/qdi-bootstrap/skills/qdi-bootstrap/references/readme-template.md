## What is QDI?

QDI splits AI-assisted development into 3 phases, each running in a **fresh context** with structured artifact handoff. This prevents context degradation and ensures quality on medium-to-large tasks.

Based on Dex Horthy's Context Engineering (QRSPI) and Dmitry Bereznitsky's "Process over Prompts," adapted into a streamlined 3-phase workflow.

## Commands

| Phase | Command | When |
|-------|---------|------|
| Questions | `/qdi-questions <task description or task ID>` | Start here for medium-to-large tasks |
| Design | `/qdi-design <task ID>` | After Questions |
| Implement | `/qdi-implement <task ID>` | After Design |
| **Work** | `/qdi-work <description or task ID>` | **Small fixes, bugfixes — one conversation** |

> Clear context between each phase — open a fresh session before running the next command.
> **Work** is a single-conversation shortcut — no phase breaks needed.

QDI adapts QRSPI into 3 phases: **Q**uestions → **D**esign → **I**mplement. Each phase runs one or more stages internally, with sub-agents for isolation. **Work** is a lightweight all-in-one mode for small tasks.

| Phase | Sub-phase | Who | Output | User action |
|-------|-----------|-----|--------|-------------|
| **Questions** | First interview | Main ↔ user | Interview notes | Answer questions |
| | Codebase scan | Sub-agent | Scope context | — |
| | Follow-up interview | Main ↔ user | Refined understanding | Answer follow-ups |
| | Spec writing | Main agent | `NN-spec.md` | Review (optional) |
| **Design** | Research | Sub-agents | Context & findings | — |
| | Solution proposals | Main ↔ user | Multiple options | **Pick approach** |
| | Outline | Main ↔ user | `NN-design-outline.md` | **Review (mandatory)** |
| | Implementation plan | Main agent | `NN-implementation-plan.md` | Review (optional) |
| **Implement** | Branch setup | Orchestrator | Git branch | — |
| | Slice execution | Sub-agents | Code | **Test first slice** |
| | Draft PR | Sub-agent | PR link | **Code review** |
| | Documentation | Main ↔ user | CLAUDE.md / memory | Confirm |
| | Refinement | Main ↔ user | `NN-refinement.md` | Choose next step |
| **Work** | All-in-one | Main + sub-agents | `NN-work-log.md` | Go with the flow |

## Quick Start

**Full pipeline** (medium-to-large tasks):
```
/qdi-questions <describe your task or paste a ticket>
```

Then follow the recommendations at the end of each phase:

```
/qdi-questions  →  /qdi-design  →  /qdi-implement
     ↓                  ↓                ↓
  spec.md        design-outline    code + PR
                 + impl plan
```

Clear your context (start a new conversation) between each phase.

**Quick fix** (small tasks, bugfixes):
```
/qdi-work <describe the fix or reference a task ID>
```

Single conversation. Same artifact folder, same numbering. Use when the full pipeline is overkill.

## Refinement Loop

After implementation, if refinements are needed:

```
/qdi-implement  →  refinement  →  /qdi-design  →  /qdi-implement
                       ↓               ↓                ↓
                  04-refinement   05-design        06-implementation
```

Or skip Design for minor changes:

```
/qdi-implement  →  refinement  →  /qdi-implement
                       ↓                ↓
                  04-refinement   05-implementation
```

Artifact numbers always increase across iterations.

## Numbering Rules

1. Both folders and files carry the number prefix: `NN-phase/NN-artifact.md`
2. Design produces two files sharing the same number
3. Numbers **never decrease** — always scan for the highest existing NN and increment
4. Adding a file to an older folder: the file's number must be ≥ the highest existing number anywhere

## Tips

- **Small fixes** → `/qdi-work`. Full pipeline for everything else.
- **Read the code.** Review the PR, don't just trust artifacts.
- **Restart over repair.** If a phase goes sideways, restart with fresh context.
- **Numbers only go up.** Artifact numbering is globally monotonic within a task.
- **No code in Design.** Design uses structured text and pseudocode only.
- **Work can escalate.** If `/qdi-work` discovers the task is bigger than expected, it suggests switching to the full pipeline.
